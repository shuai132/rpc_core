RPC 请求重试：
- 问题：发送期间触发超时重试时，旧发送失败会错误结束新重试，导致有效响应被丢弃。
- 修复：C++ 和 Rust 都按具体发送尝试校验结果，旧尝试不再影响正在等待响应的新重试。

流连接回调：
- 问题：保存的发送回调在连接销毁后仍访问原对象，可能触发内存访问错误。
- 修复：发送回调检查连接生命周期，连接销毁后安全返回发送失败。

二进制数据反序列化：
- 问题：解码失败后长度与缓冲区不一致可能导致越界读取；从自身缓冲区解码也可能访问已释放内存。
- 修复：完整校验并复制数据后再替换目标，失败时保留原值，支持从原缓冲区解码。

枚举反序列化：
- 问题：越界值被静默截断为其他枚举值，截断数据也会改写原值。
- 修复：校验枚举底层整数范围，失败时保留原值，同时兼容原有负值编码。

Rust 服务端监听：
- 问题：在会话回调内停止服务端后，旧监听任务仍会接受队列中的连接。
- 修复：停止或重启时立即使旧监听任务失效，回调返回后不再继续接入连接。

Pair 反序列化：
- 问题：含引用成员的 pair 被当成普通值对象写入，可能破坏内存；解码失败也会覆盖原值。
- 修复：移除不安全的类型转换，完整解码后再赋值，保留引用绑定和失败时的原值。

RPC 发送状态：
- 问题：注册定时器期间发生同步断线时，C++ 和 Rust 仍可能发送尚未发出的请求。
- 修复：实际发送前重新校验就绪状态，离线时结束调用并移除响应登记，旧定时器不影响后续重连调用。

紧凑布局结构体序列化：
- 问题：序列化宏直接引用未对齐的标量成员，触发未定义行为，部分平台可能崩溃。
- 修复：通过对齐临时值读写标量，保持字节格式及普通字段行为；新增严格失败的内存与未定义行为检查任务。

JSON 错误日志：
- 问题：C++ 解码及 Rust 响应序列化直接记录异常原文，可能将消息中的敏感值写入日志。
- 修复：只记录失败状态，保留原有错误处理，并覆盖解析错误及自定义转换异常的日志检查。

字符串原地解码：
- 问题：输入引用目标字符串缓冲区时，调整长度和重叠复制会破坏数据，扩容还可能访问已释放内存。
- 修复：重叠输入先保存再替换目标，支持子区间及宽字符；普通解码继续复用已有容量。

请求结束回调：
- 问题：将无参数的 finally 回调设为空后，请求结束会抛出异常，可能终止程序。
- 修复：空回调统一表示清除后续调用的回调，正在执行的请求继续保留原有回调。

FlatBuffers 解码：
- 问题：复用对象时，新消息省略的字段会保留旧值；已失败的输入仍可能改写目标，无效缓冲区也缺少前置检查。
- 修复：校验输入后完整替换对象，缺省字段恢复默认值；拒绝空指针和超限输入，失败时保留原对象。

JSON 输入校验：
- 问题：已失败的输入仍会触发 JSON 转换并覆盖目标；空指针配合非零长度还会触发未定义行为。
- 修复：解析前拒绝无效输入，插件保留已有错误状态，不改写目标或调用用户转换函数。

Rust 消息分发：
- 问题：同时包含请求和响应标记的畸形消息会被当作请求执行，与 C++ 行为不一致。
- 修复：仅接受唯一消息方向，畸形消息不执行回调、不发送回复，也不结束等待中的请求。

Rust 客户端停止：
- 问题：RpcClient 返回共享句柄，但 stop 要求独占可变引用，正常调用无法编译。
- 修复：允许通过共享句柄及连接回调停止客户端，关闭连接并取消自动重连，仍可手动重新打开。

Rust 请求回调替换：
- 问题：旧回调捕获的 Dispose 在释放时取消同一请求，会触发重复可变借用并导致 panic。
- 修复：响应、超时和结束回调替换后，先释放内部借用再销毁旧捕获，允许取消或重新配置请求。

Rust 订阅与定时器回调：
- 问题：替换命令或定时器回调、取消订阅时，旧回调释放触发的请求取消会造成分发器借用冲突。
- 修复：解除 RPC 和分发器借用后再释放旧回调，取消回调可安全重新配置 RPC，迟到响应及超时不会重复结束请求。

Rust 网络回调替换：
- 问题：客户端、服务端、会话和连接通道释放旧回调时，捕获对象的析构若重新注册回调会触发借用冲突。
- 修复：统一在内部借用结束后释放旧回调，允许析构过程安全重新配置网络回调。

C++ 头文件包含顺序：
- 问题：先包含 RPC 或请求声明头、后包含总入口时，序列化模板查找失败，整数和字符串调用无法编译。
- 修复：消息封装显式包含序列化依赖，补齐三种入口顺序的编译及往返调用检查。

批量请求取消：
- 问题：同一请求重复加入取消组后，取消回调中发起的新调用也会被后续重复登记取消。
- 修复：C++ 和 Rust 每轮按登记顺序各取消一个请求一次，后续仍可重新登记并取消。

Rust 无参数调用：
- 问题：未设置消息体时发送空字节，导致无参数处理函数无法解码，默认 ping 也返回响应解码失败。
- 修复：省略消息体时发送代表 unit 的 JSON null，与显式传入 () 的行为一致。

Rust 重连通知：
- 问题：旧请求结束回调关闭或重开客户端后，仍会收到已失效连接的打开通知。
- 修复：请求结束回调执行后重新检查连接状态，跳过失效通知，后续新连接正常通知。

响应解码重入：
- 问题：自定义响应解码取消并复用请求后，旧响应仍可能触发旧回调并错误结束新调用。
- 修复：C++ 和 Rust 在解码后核对调用身份，丢弃已失效的解码结果，新调用继续等待自己的响应。

Rust 参数转换：
- 问题：订阅、取消订阅或连接时，自定义命令名或地址转换若重新配置同一对象，会触发借用冲突并 panic。
- 修复：执行用户转换时不持有 RPC 内部借用，转换后正常完成订阅变更或连接。

容器元素解码：
- 问题：数组、顺序容器和集合在元素长度或数据不完整时，仍会调用自定义元素解码器。
- 修复：先验证元素数据边界，失败后立即停止，不执行无效元素的解码逻辑。

响应解码中的会话重置：
- 问题：解码尚未结束，请求登记已被移除，会话重置漏掉该请求，无法结束旧调用或立即复用。
- 修复：C++ 和 Rust 保留登记至响应处理结束，重置可及时完成旧调用；异常退出也会清理，且不误删新登记。

流缓冲区校验：
- 问题：空指针配合非零长度传入分帧收包或打包接口，会读取无效内存或发送残缺帧头。
- 修复：打包前拒绝无效缓冲区，收包返回失败并等待重置；零长度空缓冲区仍正常支持。

延迟回复状态：
- 问题：自定义序列化重入可能重复发送回复，发送异常也可能让后续尝试一直返回忙。
- 修复：序列化前锁定本次回复，重入返回忙；异常退出恢复可重试状态，成功回复仍只发送一次。

Rust 网络任务退出：
- 问题：收包或关闭回调 panic 后，任务计数未归零，连接关闭等待和后续重开会卡住。
- 修复：读写任务退出时自动关闭连接并完成计数清理，也覆盖尚未运行就被丢弃的任务。

C++ 无异常构建：
- 问题：新增异常退出测试无条件使用 try/throw，导致关闭异常的测试构建失败。
- 修复：仅在启用异常时运行异常专用测试，其余测试保持覆盖，并增加无异常构建的 CI 检查。

Asio 协程构建：
- 问题：启用协程功能后未传递 C++20 和 Asio 依赖，直接包含 RPC 头文件会编译失败。
- 修复：功能开关自动配置依赖，头文件显式包含 Asio，并将该功能配置加入持续集成验证。

响应完成回调：
- 问题：C++ 响应回调抛出异常或 Rust 响应回调 panic 时，会跳过该次调用的 finally。
- 修复：异常展开时仍执行一次 finally 并保留原异常传播，不影响回调内新发起的请求。

响应解码异常：
- 问题：自定义响应解码器异常退出后，请求会一直保持忙碌并持有自身，无法再通过超时释放。
- 修复：C++ 和 Rust 都会以响应解码错误结束该次调用并释放资源，同时保留异常传播与重入复用行为。

超时回调异常：
- 问题：超时回调异常退出时，请求和超时登记未清理，导致请求保持忙碌并滞留资源。
- 修复：C++ 和 Rust 均会结束当前超时调用并清理旧登记，保留原异常传播，不影响回调内新发起的调用。

会话批量重置：
- 问题：一个请求的完成回调异常退出，会中断其余旧请求的重置，造成请求和资源滞留。
- 修复：先结束所有旧请求，再传播第一个回调异常，同时保留回调中新发起的请求。

批量取消请求：
- 问题：取消回调异常会中断取消组，导致后续请求未取消。
- 修复：先完成当前批次的取消，再传播首个回调异常，并保留重复登记和请求复用的既有行为。

请求发送异常：
- 问题：发送函数或计时器登记异常退出时，请求仍保持忙碌，甚至无法通过超时释放。
- 修复：清理当前发送尝试并结束调用，保留原异常传播，不覆盖已完成响应或重入产生的新尝试。

Rust 自动重连：
- 问题：连接关闭或连接失败回调 panic 后，已配置的自动重连被跳过。
- 修复：回调异常退出时仍按当前策略调度重连，并尊重回调内主动关闭客户端的操作。

Rust 连接入口：
- 问题：主机名转换异常会提前改变客户端状态，使原连接尝试或重连计时器失效。
- 修复：先完成主机名转换，再切换连接状态，转换失败时保留原连接任务和停止状态。

Rust 异步等待：
- 问题：future 克隆或替换 waker 时，waker 若重入取消请求，会触发内部借用冲突。
- 修复：在内部借用之外克隆和释放 waker，并重新检查完成状态，避免 panic 或丢失唤醒。

Rust 异步结果：
- 问题：复用请求时，后续调用会覆盖尚未取走的旧 future 响应或完成状态。
- 修复：每个 future 只接受首次完成结果，后续调用保持独立，新 future 正常接收新结果。

异步请求启动：
- 问题：替换旧回调时，其析构逻辑重入调用可能抢先启动请求，造成 future 或协程挂起。
- 修复：完整安装异步回调并启动调用后再释放旧回调，保留同步完成后再次发起调用的能力。

C++ 协程响应：
- 问题：响应完成后、协程恢复前复用请求，会把原协程的返回数据替换为后续响应。
- 修复：完成时移交当前响应，排队等待恢复的协程始终取得自己的结果。

Rust 网络配置：
- 问题：socket 发送和接收缓冲区大小配置一直未应用，设置无效或不合法的值也会报告连接成功。
- 修复：每次连接时校验并应用缓冲区设置，零值保留系统默认；失败时关闭该连接，客户端报告失败，服务端继续接受后续连接。

流连接分帧：
- 问题：接收回调抛异常后丢失部分输入，却继续解析后续字节，可能把正文误识别为新消息。
- 修复：异常传播时清理暂存输入并拒绝继续接收，显式重置后才开始解析新数据流。

Rust RPC 连接初始化：
- 问题：替换旧收发回调或计时器时，其析构逻辑若重入客户端配置，会触发借用冲突并中断连接初始化。
- 修复：释放客户端内部借用后再安装回调，允许析构中修改客户端设置或关闭连接，并避免关闭后误报连接成功。

Rust 连接通知异常：
- 问题：连接成功或新会话通知 panic 后，新建 socket 和读写任务仍在后台运行，连接无法正常释放。
- 修复：通知异常退出时关闭本次连接，保留原异常传播，并保留客户端重连、主动重开和服务端重新启动的能力。

长期使用取消组：
- 问题：持续登记短期请求或重复登记同一请求时，过期弱引用和登记记录不断累积。
- 修复：按有效登记规模定期清理过期与重复记录，保留取消顺序和有效请求，避免每次登记都扫描整个组。

C++ 取消组重入：
- 问题：移除弱引用时释放自定义控制块，其析构逻辑若再次修改取消组，会使容器迭代失效。
- 修复：完成记录清理后再释放控制块，允许重新登记、移除和取消，并保留后续定期清理能力。

C++ 优先队列反序列化：
- 问题：自定义元素解码中途抛异常后，已读入元素未恢复堆顺序，继续访问队首或出队可能得到错误结果。
- 修复：异常传播前按目标比较器重新建堆，保留成功解码的元素，使队列能够继续使用。

C++ 智能指针反序列化：
- 问题：输入由目标指针持有时，提前替换目标会释放仍在读取的缓冲区；解码失败也会丢失原值。
- 修复：完整解码后再替换目标，失败时保留原指针与内容，并继续使用原有自定义删除器。

C++ 嵌套解码对象复用：
- 问题：子归档读取失败后残留错误标志，即使随后载入完整数据，也无法继续解码。
- 修复：成功载入新子归档时清除旧错误，同时保留父归档失败后的停止行为。

C++ 协程请求启动异常：
- 问题：发送器或计时器注册同步抛异常时，协程先被清理回调完成，异常随后逃出启动过程并可能终止进程。
- 修复：启动结束后统一交付结果或异常，保证协程只完成一次，保留请求复用及旧结果隔离。

Rust RPC 销毁清理：
- 问题：销毁时一个完成回调 panic 会跳过其余待处理请求，导致请求挂起且自持有引用无法释放。
- 修复：先完成所有待处理请求并释放其自持有引用，再传播第一个 panic。

C++ 请求配置生命周期：
- 问题：旧回调析构、自定义序列化或旧控制块释放期间，请求可能被提前销毁，配置接口继续访问对象或抛出 `bad_weak_ptr`。
- 修复：配置期间保留请求所有权，并将有效共享指针返回调用方，支持配置完成后继续调用。
